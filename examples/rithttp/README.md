# RITHTTP1 output-pipe codecs and fixtures

Targets executor [PR #247](https://github.com/ritual-net/executor-go-internal/pull/247) at `75c04e3423933887aec74ceea378ce214f01f95c`, with `ritual-go-common` at `ed73a3f765d8f3762013b32cb8b373d9009fb204`. Consumers need only public dependencies:

```bash
cd examples/rithttp
bun install --frozen-lockfile
bun run typecheck
bun test  # public Foundry forge and solc 0.8.30 must be available
```

- `rithttp.ts`: canonical four-field request encoder, RITOUT1 outer decoder and indexed encoding-4 pipe-result decoder. Encoding performs structural checks; executor selector/policy validation and normalized DA destination checks remain authoritative.
- `RITHTTP1.sol`: matching pure Solidity ABI codecs, adapted for this interface. It is not an imported upstream library or a replacement for consumer callback authentication, expected pipe metadata, limits and failure policy.
- `rithttp-private-io.ts`: unchanged multi-recipient input artifacts, current RITPIPE1 record encryption/decryption, STREAM commitment verification and CONTRACT/DA byte verification. ECIES configuration is explicit per call (12-byte GCM nonce).

Copy these files into a consumer project as needed. Pass the request encoder's hex as raw bytes into the existing outer body, e.g. `hexToBytes(encodeRitHttp1(...))` when a wrapper expects `Uint8Array`; do not UTF-8 encode the hex string. Per-pipe empty recipient keys explicitly mean plaintext. Both public and encrypted STREAM tokens are base64 binary records/ciphertexts. CONTRACT/DA collect independently and encrypt once; DA is not an archive of live ciphertext frames.

Read the [wire reference](../../skills/ritual-dapp-http/references/rithttp1.md) and [private-I/O reference](../../skills/ritual-dapp-http/references/rithttp1-private-io.md). Match result count/index/kind/encoding/encryption to the admitted request before using these helpers. Obtain job and expected commitments from independently authenticated canonical settlement. Keep live text provisional; a successful usage pipe can survive failure of the live delivery pipe. Early errors may have no pipe array.

`testdata/private_io_vectors.json` is retained byte-for-byte from the pinned shared-codec source. Tests use its **input artifact** cases only; its historical stream/archive section is not the output-pipe interface. `testdata/output_pipe_vectors.json` is a separate capture generated by the pinned executor itself, covering buffered/SSE, all-public, mixed public/private, all-encrypted outputs, input refs and stream failure with retained usage. Digests and source information are in `provenance.json` and independently pinned by tests. Fixture keys are public test material; never use them for funds or secrets.

To regenerate output fixtures with internal source access, check out the two pinned revisions, place `ritual-go-common` beside the executor (its local go.mod replacement), copy `testdata/generate-executor-vectors_test.go` into `internal/rithttp/consumer_vectors_test.go`, then run from the executor:

```bash
RITHTTP_VECTOR_OUTPUT=/absolute/path/output_pipe_vectors.json \
  go test -run '^TestExportConsumerVectors$' -count=1 ./internal/rithttp
```

The generator uses upstream test doubles for storage/publisher and a local HTTP SSE server. ECIES is randomized: a new capture has different ciphertext/digests and requires an explicit provenance/test-pin update. Consumer tests need neither Go nor access to private repositories. Bun tests verify exact Go/viem request bytes, Go-produced result/ECIES/commitment interpretation, binding/tamper rejection, current input artifacts, and six Solidity comparisons. They do not prove live cloud storage availability, deployed executor compatibility, or end-to-end application admission/billing policy.
